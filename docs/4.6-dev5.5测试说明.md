# ModRetro Chromatic 4.6-dev5.5 开发测试记录

日期：2026-11-17。当前是开发测试版；原配《俄罗斯方块》保存、读档和完全断电后恢复均已通过；用户另反馈《塞尔达》也可用。其他卡带与性能仍需逐项验收。

## 已证实的问题与修正

8 GB microSD 已在真机完成 SDMMC 初始化与 FAT 文件系统挂载（ESP_OK）。先前的“无内存卡”问题由 dev5.2 的 ESP32 IO0 启动后释放修正解决。此后仍存在的“硬件出错”发生在 FPGA 捕获阶段，不能解释成内存卡未插入。

独立综合对照定位到本机 GowinSynthesis V1.9.12.04-1 生成结果与 RTL 语义不一致：

| 仅改变的写法 | 综合产物对照结果 |
|---|---|
| 去掉 `abort_state`、`standby_req` 两个输入端口的 VHDL 默认值，保留显式连接 | 中止信号恢复连接 `ss_abort`；冻结标志写入恢复连接 `freeze_cart`。旧产物错误连接到周期计数器。 |
| 将初始化的整数长度数组改为显式纯函数选择字数 | WRAM、VRAM、OAM、零页 RAM 长度恢复固定正确值，去除非预期计数器依赖。各 RAM 容量的原始长度保持一致。 |
| 去掉 `BUS_Dout` 输入默认值，保留显式 64 位数据总线连接 | 内部寄存器捕获不再受非预期计数器位控制；状态引擎模块中不再出现该无关计数器信号。 |

处理器的 `T80.isGBC` 输入也发现相同默认值错接，原本应固定的 GBC 模式判断错误依赖计数器；去掉输入默认值后，T80、GBse 及状态引擎均不再引用这个无关计数器。此项是否解决用户 GBC 卡带黑屏仍待真机确认。

输出和内部状态的初始化保持原意。故障中止保护、文件格式、卡带支持范围没有借此扩大。新加失败定位查询保留失败时的捕获位置、内存握手和暂停标志，避免只凭菜单提示判断原因。

## 验证范围

保留 ROM-only、8 KiB、32 KiB 的状态保存/加载及中断测试；新增真实保存管理器参与的 MBC5 联合测试，以及真实 CPU 在两种速度、多个指令相位自主进入捕获的回归。仿真中的 GPU、卡带、内存模型范围以测试注释为准，不能替代实体卡恢复验收。

另外核对综合后的实际接线，防止只验证源代码仿真而漏掉生成电路差异。包含 T80 输入修正与资源精简的组合版本已有 44 项回归通过（包含完整 8 MiB 扫描）。构建脚本会在布局布线前运行结构检查，要求保存中止信号进入状态引擎的 17 个状态寄存器与睡眠寄存器、冻结标志取自正确暂停请求，且状态引擎不包含无关周期计数器；未知综合布局直接报错，需人工检查。此检查不等于完整逻辑等价证明。最终布局布线、时序检查、镜像校验与真机结果将随本轮测试记录更新。

## 卡带兼容性跟进

- 用户报告正版《马里奥大陆》可运行，但即时存档返回“不支持”。当前即时存档仅开放 ROM-only 与指定 MBC5 几何；此提示不等于普通游戏存档损坏。
- 用户报告两张新版 GBC 单卡（《塞尔达》《星之海洋》）在官方固件可运行，本开发固件黑屏。按兼容性回退跟进，不判断卡带损坏。需分别检查启动与即时存档。
- 支持的 MBC5 在启动时会先扫描整份 ROM，2/4/8 MiB 大约需要 2/4/8 秒；不支持的类型读取卡头后应直接放行启动。不能用存档支持范围阻止正常游戏。

## 真机验收结果

1. **已通过**：《俄罗斯方块》状态捕获约 70 ms 完成，完整 10,341 字写入、同步及关闭文件后返回 Saved，进度 100%。MCU 和 FPGA 均已刷写并校验。
2. **已通过**：用户确认继续游戏后读档，正确回到保存位置；日志确认 10,341 字载入，恢复阶段约 90 ms，返回 Restored。
3. **已通过**：用户按 OFF、拔 USB、等待后重新开机，确认仍能恢复保存位置。
4. **部分通过**：用户另反馈《塞尔达》也可以；未单独确认它的断电恢复范围。《星之海洋》本轮尚未复测，不宣称已解决。

尚未通过的项目不得描述为已经支持或实测成功。测试固件请保留可用的回退版本，先用可重开的游戏进度验证。

## 构建进度

第一份接线正确的候选在布局布线时达到 98% CLS，占用接近上限，仍有未布通连接，因此没有刷入真机。经过调色板读回、数据寄存器共享、可选诊断存储和分步 CRC 等价优化后，最终候选已完成全部布线和原约束下的正时序检查；44 项全量回归通过。《俄罗斯方块》基础真机验收已通过；其他卡带范围仍以逐项记录为准。

资源精简的隔离对照与已验证范围见[记录](../verification/resource-dev55.md)。此次检查还发现上游音频状态的 GBC wave RAM 槽位复用问题，记录为[待修缺口](../verification/audio-snapshot-gap.md)；当前测试不代表已验证所有游戏的音频现场恢复。

## 下次继续的项目

- 《马里奥大陆》当前可以玩，但即时存档仍提示不支持。需扩展实际卡带类型，优先确认卡头及 MBC1/无卡带 RAM 的几何；不能把“原游戏没有自带存档”当成无法做即时存档的原因。
- 存读速度仍慢。现协议每 8 字节往返，115200/8N1 下 10,341 字的纯线速下限约为保存 18 秒、读档 25 秒；实际还有遥测、调度及 SD 开销。
- 已定位可先做的 MCU 优化：UART1 驱动默认接收阈值为 120 字节，菜单持续遥测时可额外造成较大批处理等待。下次先验证阈值 8 字节、空闲超时 1 符号，保持原波特率及 CRC/索引握手，实测耗时并复查蓝牙播放。**此优化尚未实施或刷入。**
- FPGA 内部 UART2 硬绑分频，单改 BAUD_RATE 参数或 MCU 波特率无法配套提速。更高波特率、流水与块协议需要单独验证。
- 当前开发进度已保存，下次按上述顺序继续验证。
