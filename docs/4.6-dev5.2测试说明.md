# ModRetro Chromatic 4.6-dev5.2 测试记录

记录日期：2026-11-17。dev5.2 已完成构建、时序检查与刷写。**真机 SD 初始化和文件系统挂载成功；即时存档捕获仍失败，尚未完成保存或恢复验证。**

## 已观察到的结果

- dev5 的 MCU 和 FPGA 均已写入掌机，刷写工具校验成功；这只确认镜像写入，不代表存档功能通过验收。
- 使用一张 8 GB microSD 卡首次保存时，界面返回 `No SD card`。该提示来自挂载超时或未找到设备的错误分类，并非独立插卡检测脚的结论。
- dev5.1 补充 DAT3 上拉后仍然失败，诊断停在命令 51（读取 SCR）。此前命令已有响应，不能将结果简单解释为卡完全未通电或没有插入。
- 诊断已区分底层 `nativeRet` 与 `cmd.error`：前者为 `ESP_OK` 时，命令或数据传输仍可能通过后者报告超时，不能只看函数返回值判断成功。

## dev5.2 调整及依据

FPGA 原先持续主动拉高 ESP32 IO0。此次改为在正常启动时主动拉高，在 ESP32 EN 释放后继续保持约 124.5 ms，再将 IO0 输出设为高阻，由强上拉维持默认电平；主机请求进入下载模式时，拉低请求始终优先。

依据是 ChroMagic 开发者的[原始 SD 初始化修复提交](https://github.com/cursedtoast2/ChroMagic/commit/e611a1ef36eb9aa93f706d836f5b0e46129d7137)，以及后续[新板启动与 IO0 释放修复 PR #16](https://github.com/cursedtoast2/ChroMagic/pull/16)。后者记录了与本次相同的 `responded=1 command=51` 故障，并报告持续推挽拉高 IO0 会导致 SD 初始化失败。它提供了修复方向，不能代替本机验证，也不能据此断言本机 GPIO0 与 GPIO2 的具体板级连接。

本次启动保持、释放及下载拉低优先的逻辑仿真已通过。Espressif 的[SDMMC 示例排错说明](https://github.com/espressif/esp-idf/blob/v5.3/examples/storage/sd_card/sdmmc/README.md)也将首次 SCR 读取超时与 DAT0／GPIO2 连线问题联系起来；[SD 上拉要求](https://docs.espressif.com/projects/esp-idf/en/v5.3/esp32/api-reference/peripherals/sd_pullup_requirements.html)要求即使在 1-bit 模式下也正确处理数据线的上拉。

## 当前状态与待验收项

- dev5.2 配套 MCU 与 FPGA 已刷写并由工具校验。FPGA 所有路由完成，setup、hold、recovery、removal 和 pulse width 检查均无违规。
- 真机日志确认 SD 文件系统挂载返回 `ESP_OK`；末次命令为 13，响应及错误状态正常。8 GB 卡无需因之前的“无内存卡”提示拆机或格式化。
- dev5.3 定位日志确认失败发生在 FPGA 捕获阶段：约 260 ms 后返回结果 3，MCU 尚未取回第一个状态字。250 ms 捕获停滞保护已退出操作；这并非成功存档。
- dev5.4 增加独立诊断查询，在失败时保留时钟暂停、原始状态请求及内存握手信息，用于区分等待 VBlank、等待冻结与等待内存完成；它本身不宣称修复捕获。
- 待通过真机保存、继续游戏后读档，以及关机重启后读档。尚无主流卡带即时存档恢复通过的实测结论。

完成上述实测前，本版只能作为开发测试版本；不得将“已编译”“已刷写”或“仿真通过”写作真机存档成功。
