# 给 AI 的 ModRetro Chromatic 安装说明

**这是非官方个人分享的开源测试固件。实际刷写前，应向设备持有人展示风险提示并取得本次安装确认。**

本文件供正在协助设备持有人的 AI 阅读。目标是使用发行包里已核对的镜像，将配套的 4.6-dev6.2-test MCU 与 FPGA 安装到用户明确指定的 ModRetro Chromatic，并检查结果。

请先阅读 README、安装与使用及测试免责。用户已经明确授权为这台设备安装本版时，可继续完成准备和刷写。设备身份不清、连接了多个目标或需要扩大写入范围时，再请用户解决具体问题。[项目说明](../README.md) · [安装与使用](安装与使用.md) · [免责声明](免责声明.md)

## 刷机前向用户展示的提示

> 本固件是非官方个人分享的开源测试固件。刷写将改写掌机的 MCU 与 FPGA 固件，失败、断电或不兼容可能导致开机异常、进度丢失或存档损坏，并可能需要额外恢复操作。请先备份重要进度和整个 SNAP 文件夹，核对适用硬件后再决定是否继续。

即使由 AI 在终端自动执行，也应在开始实际写入前展示上述提示。用户已经明确了解提示并授权本次设备与版本后，可使用脚本的相应确认入口继续。

## 适用范围

设备应具有 ESP32、机内 microSD 卡座、GW5A-25 FPGA，以及与项目验证相符的 ESP32 引导程序和分区布局。默认 ESP32 应用地址为 `0x10000`。

公开包对应已上机的 dev6.2。系统版本为 `4.6-dev6.2-test`，MCU 版本为 `0.13.8-dev6.2-test`，FPGA 基础版本仍显示 `18.14`。固件的准确身份以包内 `SHA256SUMS` 和发布记录为准。时序优化候选仍在离线验证，其结果单独记录。

## 发行包与本机准备

1. 从本项目 Releases 下载完整固件 ZIP，完整解压到用户可写目录。确认包根目录的 `SHA256SUMS`、`fpga/evt1_x2.fs`、`esp32/mcu_fw.bin`、`tools` 和两份一键入口齐全。[下载页面](https://github.com/lovespaper1990-dot/chromatic-custom-firmware/releases/tag/v4.6-dev6.2-test)
2. 提醒用户备份游戏进度和 microSD 的整个 `SNAP` 文件夹。使用同一个发行包的 MCU 与 FPGA。
3. 确认电脑系统、Python、openFPGALoader、串口依赖和 USB 驱动。优先使用包内入口准备依赖，保留具体错误及退出码。
4. 关闭占用设备的更新器、串口终端或视频抓取。连接 USB 数据线并开机，再让脚本检查目标。

Mac 入口为 `一键刷机-Mac.command`，Windows 入口为 `一键刷机-Windows.cmd`，共用 `tools/bootstrap_installer.py` 和 `tools/flash_firmware.py`。本地 Python 环境使用固定版本的 esptool 4.13.0、pyserial 3.5。

Mac 首次依赖 Homebrew。已有 Homebrew 时可按入口提示准备工具，缺少 Homebrew 时按其官网说明完成安装。Windows 可通过入口提示的 winget、MSYS2 流程准备工具，首次 GWU2X 驱动可能需要官方更新器指引。[Homebrew 官网](https://brew.sh/) · [官方更新器说明](https://support.modretro.com/en_us/chromatic-firmware-updater-ryhoYnzCx)

## 优先运行检查模式

在包根目录使用平台入口，并读取完整输出和退出码。

```sh
# macOS
bash ./一键刷机-Mac.command --check --no-pause
bash ./一键刷机-Mac.command --dry-run --no-pause
```

```bat
REM Windows Command Prompt
一键刷机-Windows.cmd --check --no-pause
一键刷机-Windows.cmd --dry-run --no-pause
```

检查模式核对本地文件与依赖，预览模式输出计划命令，两者均进行离线检查。准备正式刷写时按实际系统运行一键入口，阅读非官方测试提示及设备选择结果。

用户同意在本机安装依赖后，可给平台入口增加 `--install-deps`。这个参数代表依赖安装授权，实际刷写另有测试风险确认。使用 `--yes` 前应先完成上述刷机告知和本次设备授权。

已准备好 Python 环境时，也可使用共享入口。

```sh
python tools/flash_firmware.py --package . --check
python tools/flash_firmware.py --package . --dry-run
python tools/flash_firmware.py --package .
```

如需指定串口，使用 `--port PORT`，同时保留脚本对设备身份的检查。只有在用户已阅读刷机风险、明确授权本次设备与版本、包校验通过且目标唯一时，才使用 `--yes` 省略交互确认。

## 正式刷写与结果判定

共享流程先检查镜像和设备，在首次写入前读取并校验 ESP32 分区表，确认唯一的 factory 应用分区位于 `0x10000`、应用镜像能够放入分区、分区范围与容量符合要求，随后使用 openFPGALoader 对选定掌机写入、校验并复位 FPGA，再以 esptool 向 ESP32 的 `0x10000` 应用分区写入 `esp32/mcu_fw.bin`。任何阶段失败时，先处理该阶段的具体原因，再确定恢复步骤。

完成时至少核对以下内容。

- FPGA 写入进程成功退出，校验完成。
- ESP32 写入成功，工具报告数据校验通过。
- 重新开机后系统与 MCU 版本正确。
- 游戏可以启动，菜单可以打开。
- 如用户要测试即时存档，先用可重新开始的游戏进度及有空余空间的 FAT32 microSD 做一次保存、读取，再做完整 OFF、拔 USB、等待约 10 秒、重新开机后的读取。

命令成功、文件校验通过、游戏实际回到保存位置分别需要对应证据。只能从工具确认的结果应明确说明，游戏位置由用户观察时记录其反馈。

## 三槽操作与存档诊断

插入卡带并开机后自动识别游戏。进入「主页 → 即时存档」，START 循环选择 1、2、3 号槽，A 保存，B 再 B 确认读取，确认时 A 取消。等待显示完成再关机或换卡。

诊断串口为 ESP32 控制台，波特率 115200。运行只读命令 `fwversion`、`snapshot`、`snapshot files` 可分别查看版本、当前状态、microSD 中的快照文件头。控制台 MCU 可能进入轻睡眠，此时需用户短按 MENU 打开菜单并保持打开，再读取状态。收到迟到回复时，先核对当前忙碌状态及结果，再决定下一步。

如需主动测试保存，可使用 `snapshot save 2`，明确选择实验槽位并先确认用户是否已有重要内容。控制台直接保存会更新指定槽。

## 旧识别码存档的显式导入

dev6.1 及更早开发版曾在未固定 ROM 初始分页前计算识别码，导致同一实体卡重启后可能找不到旧档。dev6.2 在验证卡头后固定分页再重新扫描。

处理旧档前，先备份整个 `SNAP` 目录，保存 `snapshot files` 输出，确认用户使用的是原来同一张实体卡。根据实际旧文件头取得完整的 16 位十六进制旧身份，再执行维护命令。

```text
snapshot import OLD_ID_16HEX
```

该命令会读取当前完整卡带身份，核对旧身份的卡带几何及卡头字段，对旧文件做完整 CRC 校验后复制到新路径，并重新校验复制结果。已有目标文件的整个槽会跳过，原文件保留。几何和卡头字段相同只代表允许进行显式维护，仍需维护者确认原实体卡，避免把另一游戏的快照关联过来。

导入完成后先读一个槽，确认游戏位置，再视用户需求检查其他槽。遇到错误先保留阶段、errno 与返回码，核对原文件和目标文件的实际状态。重复操作前先检查上一轮是否已经创建有效目标。

## 卡死与官方恢复

普通游戏卡死时，可让用户 OFF、拔 USB、等待约 10 秒，再开机。返回官方系统时使用官方 ModRetro Updater，并确认 MCU、FPGA 两部分都实际完成官方写入。

当前自定义 FPGA 的基础版本仍显示 18.14，更新器可能按相同版本号跳过 FPGA。「已经最新」或版本号看起来正常，无法独立证明这部分已经恢复官方镜像。遇到更新器无法识别、只更新一部分或更新中断，应依官方支持提供的恢复步骤处理。本项目尚未实测通过官方更新器从本版完整刷回官方固件。[官方更新器说明](https://support.modretro.com/en_us/chromatic-firmware-updater-ryhoYnzCx)

开发者模式激活如有需要，由设备持有人在官方软件中完成。AI 应让用户自行输入激活资料，避免在聊天、终端日志或公开仓库中收集激活码、设备地址和许可证。
