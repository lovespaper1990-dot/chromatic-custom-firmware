# Chromatic 4.6-dev6-test 离线测试记录

本版增加标准 MBC1 实体卡带快照，并把快照数据改走板上的高速 SPI。当前设备仍是已验证的 4.6-dev5.5。本版的真机兼容性、耗时及蓝牙同时播放需在设备可用时实测。

## 卡带适配

标准 MBC1 的类型 01/02/03、最多 2 MiB ROM、无 RAM 或 8 KiB RAM 可进入快照。32 KiB RAM 只允许至 512 KiB ROM。会记录低 5 位、高 2 位分页寄存器、模式和 RAM 开关。无卡带 RAM 的游戏仍保存 CPU 和内部内存，可用 64 KiB MBC1 无 RAM 用例作为《马里奥大陆》的离线对照。

扫描正确读取 0x20/0x40/0x60 的低地址窗口，随后复原启动映射。通过物理选页别名保守排除 MBC1M。普通卡若出现签名碰撞也会关闭快照，仍放行游戏启动。2 KiB RAM、MBC1M、MBC2 及带时钟的 MBC3 尚未开启。现有 ROM-only 和 MBC5 范围保留。各类型和分页行为见 [Pan Docs MBC1](https://github.com/gbdev/pandocs/blob/master/src/MBC1.md)和[卡头定义](https://github.com/gbdev/pandocs/blob/master/src/The_Cartridge_Header.md)。

## 存读与校验

dev5.5 在 115200 串口逐 8 字节往返。《俄罗斯方块》的 10,341 字仅在线搬运就需约 18 秒保存、25 秒读档，再加上串口排队、菜单和 SD 开销。真机原有记录中，FPGA 捕获约 70 毫秒，恢复约 90 毫秒。

dev6 将同一份 82,728 字节状态分成 81 个最多 1 KiB 的 SPI 块。串口只负责控制，接收阈值也从 120 降到 8 字节。以当前 40 MHz SPI 频率计算，单向的 SPI 数据阶段约 17 毫秒。完整操作还包括控制命令、文件检查、卡内写入及同步，暂不把链路耗时当成端到端成绩。Analogue 的公开协议也将快照控制与批量数据搬运分开，可作为设计对照。[Analogue 快照命令文档](https://www.analogue.co/developer/docs/openfpga/host-target-commands)

每块检查 CRC16。失败、截断或中途拔卡时不提交恢复。文件仍采用原有身份、格式、A/B 代际与整份 CRC32，保留旧文件的字节顺序。只有旧 FPGA 明确不支持块传输，MCU 才选串口传输。混合版本只用于调试，测试时使用同一包的 MCU 和 FPGA。

验证使用测试数据模拟卡带与断电前后的存档文件，覆盖多种 RAM 几何、卡带换页、快速块边界、损坏数据和取消，以及原有蓝牙与屏幕总线。设备可用后，先用《俄罗斯方块》和《马里奥大陆》检查实际保存、读档耗时与断电恢复，再复测蓝牙和已能启动的 GBC 卡带。


## 构建状态

本轮 63 项组合回归通过，最终传输代码另用两种完整快照容量回归，并以 Gowin 的 DPB 模型验过 10,341 字往返。MCU 应用也构建通过。

串口测试包已完成布线和时序验证，包含 MBC1 与接收等待优化。其 FPGA 只启用 UART，适合先验卡带。复现时应用 [UART 配置差异](../verification/dev6-uart-build.patch)，时序报告见[记录](../verification/timing-dev6-uart.txt)。

SPI 分块方案已通过逻辑综合和仿真。默认布线方案在原有约束下仍有 662 条连接未布通，正在验证布线和资源优化。
