# ModRetro Chromatic 4.6-dev6.2-test 安装与使用

**这是非官方个人分享的开源测试固件。刷机失败、供电中断或兼容性问题可能造成开机异常、进度丢失或存档损坏，开始前请先备份并阅读免责说明。**

适用于配备 ESP32、机内 microSD 卡座和 GW5A-25 FPGA 的 Chromatic。本版以 MCU v4.6、FPGA v18.14 的上游工程和本项目验证过的分区布局构建。安装前核对硬件，阅读测试免责，并备份游戏进度及 microSD 上的整个 `SNAP` 文件夹。[免责声明](免责声明.md) · [当前实机结果](4.6-dev6.2-test测试说明.md)

## 下载完整发行包

从 Releases 下载 `Chromatic-4.6-dev6.2-test-install.zip`，完整解压后再运行。包根目录应能看到两个一键入口、`tools`、`fpga`、`esp32` 和 `SHA256SUMS`。GitHub 自动生成的源码 ZIP 用于阅读源码，安装需要完整固件发行包。[下载页面](https://github.com/lovespaper1990-dot/chromatic-custom-firmware/releases/tag/v4.6-dev6.2-test)

## Mac 一键入口

1. 先安装 Homebrew。已有 Homebrew 时，入口可在确认后准备 Python 与 openFPGALoader。Homebrew 安装方式以其官网为准。[Homebrew 官网](https://brew.sh/)
2. 用 USB 数据线连接掌机并开机，关闭占用掌机的官方更新器、串口终端和抓取软件。
3. 双击包内 `一键刷机-Mac.command`。首次运行按提示允许准备本地 Python 环境与刷写依赖，再阅读测试提示并确认目标设备。
4. 等待 FPGA 写入与校验、ESP32 应用写入与校验都完成。按脚本结果提示重新启动掌机。

若 macOS 提示该文件无法打开，可先检查下载来源及 `SHA256SUMS`，再按系统提供的“打开”或隐私与安全性提示处理。终端使用者可从解压目录运行 `bash ./一键刷机-Mac.command`。脚本退出时显示的缺少依赖或权限信息，均可交给熟悉 Mac 的人或 AI 按具体情况处理。

## Windows 一键入口

1. 使用 Windows x64 环境。通过 USB 数据线连接掌机并开机，关闭其他占用掌机的程序。
2. 双击包内 `一键刷机-Windows.cmd`。首次运行可在确认后通过 winget 准备 Python、MSYS2，再通过 MSYS2 的包管理器准备 openFPGALoader。本地 Python 环境会安装固定版本的 esptool 和 pyserial。
3. 首次使用 GWU2X 编程接口时，可能还需要按官方更新器指引安装 USB 驱动。出现缺少驱动或无法发现接口时，先完成对应驱动步骤再重新运行。
4. 阅读测试提示并确认目标设备，等待两部分固件写入及校验都完成，再重新启动。

Windows 入口已进行模拟流程和静态检查，原生 Windows 刷写尚待实测。winget 不可用、依赖安装失败或设备接口不完整时，脚本会显示具体原因，供手动处理或 AI 协助。

## 脚本会做什么

一键入口会先检查发行包镜像、校验清单、依赖和目标设备，并在首次写入前读取、校验 ESP32 分区表。只有应用分区位置、容量和范围符合要求时才继续。确认后，先通过 GWU2X 写入并校验配套 FPGA，再把 ESP32 应用写入本项目使用的 `0x10000` 分区。

刷写流程遇到失败会停止。两个目标或多个掌机同时连接时，需要先明确本次设备。排错过程中请保留当前输出，避免同时启动第二个刷写进程。

可在终端加 `--check` 检查文件与依赖，或加 `--dry-run` 查看计划命令。这两种模式进行离线检查。使用 `--no-pause` 可让脚本在终端结束后直接返回，便于 AI 或其他工具读取退出码。

## 核对版本与首次测试

重新启动后，在系统菜单核对系统版本 `4.6-dev6.2-test`、MCU `0.13.8-dev6.2-test`。FPGA 基础版本仍显示 `18.14`，配套位流以发行包内校验值确认。

准备有空余空间的 FAT32 microSD，插入一张受支持的游戏卡。先用可重新开始的一局测试保存和读取，再验证完全关机后能否恢复。当前实机验收以原配《俄罗斯方块》为主，其他卡带需逐盘确认。

## 三个即时存档槽

1. 在游戏中短按 MENU，进入「主页 → 即时存档」。掌机会按卡带内容自动匹配游戏。
2. 看右栏编号，短按 START 循环选择 1、2、3 号槽。
3. 按 A 保存，等「已存档」。再次保存会更新当前槽的进度。
4. 读档时在目标槽按 B，再按 B 确认。确认时按 A 可以取消。完成后退出菜单检查游戏位置。

每款受支持的游戏各有三个槽，每槽独立轮换两代。读取时会选择该槽最新有效的一份。空槽显示「无存档」，两代均损坏时会提示文件损坏。备份和恢复 microSD 文件时请复制完整 `SNAP` 目录，连同子目录和两代文件一起保留。

旧版有效快照通常沿用 1 号槽的路径。若早期开发版因 ROM 初始分页算出过不同识别码，可能需要维护者核对同一实体卡后显式导入。先备份并读取诊断信息，维护命令说明见 AI 安装指南。[给 AI 的安装说明](给AI的安装说明.md)

## 简体中文、蓝牙与临时待机

- 在 `System → Language` 按 A 切换简体中文。
- 耳机进入配对模式后，在「主页 → 蓝牙」按 A 搜索、按 B 选择、按 A 连接。机身滚轮用于调整蓝牙音量。dev4 已在实机验证声音及滚轮，dev6.2 蓝牙与高速存读档同时运行的压力测试仍待完成。
- 电源开关保持 ON，在游戏画面单独长按 MENU 约 1.5 秒，背光熄灭后松手。短按并松开 MENU 唤醒。短按 MENU 可进入普通菜单。

临时待机持续耗电。关机、断电或拔卡会丢失待机现场。即时存档读取的最后阶段会恢复实体卡带 RAM，等待「已读档」再关机或换卡，避免原生存档出现部分写入。

## 死机与恢复官方系统

偶发游戏卡死时，可先拨到 OFF，拔掉 USB，等约 10 秒后再开机。

要更新官方固件或返回官方系统，可使用官方 ModRetro Updater，并确认 MCU 与 FPGA 两部分都实际完成了官方写入。本定制 FPGA 的基础版本仍显示 18.14，官方更新器可能根据相同版本号跳过 FPGA。若显示「已经最新」、无法识别或只更新了一部分，应按官方支持给出的恢复流程处理，避免仅凭界面版本号认定已经恢复完成。本项目尚未实测通过官方更新器从本版完整刷回官方固件。[官方更新器说明](https://support.modretro.com/en_us/chromatic-firmware-updater-ryhoYnzCx)

## 熟悉工具后的手动刷写

先在包根目录核对 `SHA256SUMS`。macOS 使用 `shasum -a 256 -c SHA256SUMS`，Linux 使用 `sha256sum -c SHA256SUMS`。Windows 使用一键入口的检查模式核对。

确认目标后写入 FPGA，等待写入与验证完成。

```sh
openFPGALoader --detect --cable gwu2x
openFPGALoader --cable gwu2x --write-flash --verify --reset fpga/evt1_x2.fs
```

使用固定的 esptool 4.x 环境，从包根目录将 `PORT` 替换为已确认的掌机串口，再写入应用。

```sh
python -m esptool --chip esp32 --port PORT --baud 115200 --after hard_reset write_flash 0x10000 esp32/mcu_fw.bin
```

上述应用写入路径要求设备具有兼容的引导程序和分区布局。处理布局不明、完整恢复或引导程序故障时，应先确认设备情况与恢复文件，再决定具体写入范围。
