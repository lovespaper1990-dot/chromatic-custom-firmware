# 实体卡带即时存档研究与实现

更新日期：2026-11-17。本轮先完成代码、仿真和本地构建，真机测试由机主稍后进行。

## 参考资料与边界

Analogue 的公开 openFPGA 文档把休眠和手动快照建立在同一套完整状态接口上：查询支持，发起捕获，等待完成，再搬运状态文件；恢复时先准备全部数据，再通知核心提交。这里借鉴的是事务顺序，官方商业卡带核心的具体实现没有从这些文档中公开。[core.json](https://www.analogue.co/developer/docs/openfpga/core-definition-files/core-json) · [Host/Target Commands](https://www.analogue.co/developer/docs/openfpga/host-target-commands) · [Core Boot Process](https://www.analogue.co/developer/docs/openfpga/core-boot-process)

MiSTer 的 Game Boy 快照实现包含 CPU、音频、视频及内部内存状态。较新的实现为慢速卡带 RAM 增加读取请求、忙碌/完成握手，最后一次写入结束后才恢复运行。本工程沿用 Chromatic 锁定的核心，并在每个 64 位状态字外增加实体卡带访问桥，等待八个字节真正完成后再回应。[MiSTer gb_savestates.vhd](https://github.com/MiSTer-devel/Gameboy_MiSTer/blob/master/rtl/gb_savestates.vhd)

另核对了 budude2 的公开 Pocket 核心。检查到的实体模式把游戏总线直接接往卡槽，但快照 RAM 端口仍接模拟卡带的内部 RAM；不能据此认定实体卡带分页和存档已经正确恢复。这与 Analogue 官方商业核心是不同实现。[core_top.sv](https://github.com/budude2/openfpga-GBC/blob/master/src/core/core_top.sv) · [cart.v](https://github.com/budude2/openfpga-GBC/blob/master/src/gb/cart.v)

MBC5 的分页寄存器只能写，不能事后从卡带读回。因此需要在游戏运行时镜像写入，保存 9 位 ROM 分页、4 位 RAM 分页和 RAM 开关。ROM 第 0 页是有效页；RAM 开关按低四位是否为 A 判断。震动版复用了 RAM 分页位，本版不接纳。[Pan Docs MBC5](https://github.com/gbdev/pandocs/blob/master/src/MBC5.md)

## 当前实现

| 卡带类型 | ROM | 卡带 RAM | 状态 |
| --- | --- | --- | --- |
| ROM-only，类型 00 | 32 KiB | 无 | 保留已有支持 |
| MBC5，类型 19 | 最大 8 MiB | 无 | 新增代码与仿真 |
| MBC5，类型 1A/1B | 最大 8 MiB | 8 KiB / 32 KiB | 新增代码与仿真 |
| MBC1、MBC2、MBC3、RTC、震动 MBC5、特殊硬件 | — | — | 当前不支持 |

启动时先验证卡头，再按分区读取整个 ROM 计算 CRC32，结束前恢复 ROM 第 1 页。最大 8 MiB 卡带会增加约 8 秒启动识别时间。游戏仍从实体卡带运行，不保存或分发商业 ROM。

保存时等待核心到达安全点并暂停 CPU 与物理卡带时序。状态流包含核心寄存器、WRAM、VRAM、OAM、零页 RAM、调色板、分页状态和实体卡带 RAM。捕获卡带 RAM 只读不写；捕获完成恢复原分页，先让游戏继续，再由 MCU 将数据写入 FAT32 microSD 的 SNAP 目录。

读档时先验证文件 CRC、长度和完整 ROM 标识，将数据完整传入暂存内存后再暂停并恢复游戏。恢复卡带 RAM 和分页完成后才允许 CPU 继续。读档会把卡带电池 RAM 一起回退到快照内容，因此也会回退游戏自身保存的进度。

卡槽总线本身也有独立时序状态。只恢复 CPU 会遗漏保存点的地址、读入数据和读写相位。本版将其放入未使用的核心扩展寄存器 63，即状态流第 64 字，附 C507 格式标记；完整读档提交时才应用。MBC5 分页状态使用扩展寄存器 32，即状态流第 33 字。文件格式升为 CSS2，旧的 CSS1 快照及缺少总线标记的文件会在读档前被拒绝，避免带着错误相位继续运行；旧快照请先备份，再在新版重新保存。

保存失败时完成正在进行的物理访问，恢复原分页再继续游戏。读档失败可能已经改变部分内存，因此会恢复上电分页并重启游戏。迟到的内存回应由邮箱排空，不得触发旧操作或把 CPU 留在暂停状态。

## 验证与尚待实机确认

测试数据均为原创图案和计数程序，不含商业 ROM、私人游戏存档或设备标识。

- 全 ROM 扫描：独立 CRC 对照、全部 512 个分页、跨第 256 页的第九位、启动分页恢复与拔卡。
- 物理桥：完整 8 KiB / 32 KiB 捕获与恢复，禁用 RAM、9 位 ROM 分页、延迟回应、读写中断和首次请求前失败。
- 联合状态机：实际 VHDL 状态引擎、分页桥、邮箱、异步内存模型，以及内部四类 RAM；恢复前检查每个字节和分页。
- 卡槽时序与 CPU：真实 GBse 在普通速、双倍速各恢复 32 次，每速比较 8,192 个执行时钟，覆盖各总线相位和 TSTATE 1–4。关闭卡槽恢复的负对照会出现取指偏差；保留待机、DMA、调色板、UART、PSRAM 和蓝牙回归。
- 时序优化后补测 HALT、中断唤醒、STOP 和外部 DMA。每速再恢复 16 次、比较 3,072 个执行点并核对 1,024 个 DMA 字节；新旧控制实现的计数程序执行轨迹也逐字节一致。地址侧 STOP 观察位保存在同一快照中。
- 文件校验：有效 CRC 的旧格式文件、有效 CRC 但缺少卡槽状态的文件均在向 FPGA 传输前被拒绝。

这些是仿真范围。原配《俄罗斯方块》、《塞尔达传说 大地之章》、GB/GBC《星之海洋》的实际卡头、快照及断电读档仍需逐盘确认，尚不能宣称全部兼容。继承核心的串口快照字段仍不完整，本版只做单机测试，不保证联机现场恢复。
