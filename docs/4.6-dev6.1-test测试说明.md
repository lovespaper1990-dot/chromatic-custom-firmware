# Chromatic 4.6-dev6.1-test 三槽即时存档

关机换好游戏卡带，装入有剩余空间的 FAT32 microSD，再开机。掌机会按卡带内容自动匹配这款游戏的快照。同一游戏可留下三个不同时间点。换另一款游戏后，会使用另一组快照。

## 操作

| 在「主页 → 即时存档」中 | 操作 |
| --- | --- |
| 选档位 | 看右栏第一行的编号。短按 START 依次切换 1/3、2/3、3/3，再按一次回到 1/3。 |
| 保存 | 按一次 A，等「已存档」。重复保存会更新当前槽。 |
| 读档 | 在目标槽按 B，再按 B 确认。确认时按 A 可以取消。空槽提示「无存档」。 |
| 旧版存档 | 直接选 1 号槽。原 microSD 上的有效 CSS2 快照使用原路径，可以继续存读。 |

中英文界面已按 160×144 屏幕检查。操作、确认、进度和错误提示最长为英文 45×44 像素、中文 37×49 像素，均能放入右栏。

每槽有两代文件。读档时会检查该槽的两代，选择最新且有效的一份。如果两代都损坏，界面会提示文件损坏。备份时将整个 `SNAP` 目录复制出来，一并保留 2、3 号槽的子目录和各代文件。

## FAT32 文件验证

使用 ESP-IDF 5.3 自带的 FatFs 和仅短文件名配置，在 64 MiB FAT32 映像中为两个游戏各写入三个槽、每槽两代。关闭映像后从独立进程打开，六个槽全部逐字节读回。手动破坏其中一个槽最新一代的校验后，该槽正确回退，其余五槽内容完整。

另一次在写入中途强制退出，六个槽都保住了原有进度。文件系统检查同时发现 FAT32 的空闲簇计数滞后。测试覆盖文件系统和存档程序，真实 SD 卡控制器断电仍需真机验证。

## 本轮修正

- 在旧版中复现了菜单数据等候写入时，后续 SPI 快照命令会改变其目的地址。新固件暂存两批完整的显示数据，等内存写完才复用。同一测试已逐字核对整屏 23,040 个像素，另覆盖队列满、帧截断和时钟停住时复位。
- 保存时再次核对卡带身份，校验快照头，写完并同步、关闭文件后重新打开校验。读档在选定槽的文件校验、SD 操作和卡带复核都成功后才开始恢复游戏。
- 偶发单个 SPI 读取块校验失败会重读一次。文件和链路校验均使用查表计算，文件操作分批进行。计时包含 SD 挂载、校验、传输和卸载。读档最终阶段会恢复卡带原生 RAM，请在「已读档」出现后再关机或换卡。

系统菜单版本为 `4.6-dev6.1-test`，MCU 为 `0.13.8-dev6.1-test`，FPGA 基础版本仍为 18.14。MCU 与 FPGA 使用同一测试包。构建使用 ESP-IDF 5.3 和 Gowin 1.9.12.04-1。沿用原时钟及引脚约束，58,345 条时序路径完成分析，建立和保持时间违例均为零。最差建立余量为 +0.750 ns，保持余量为 +0.127 ns，异步复位移除余量为 +0.056 ns。[本版布线报告](../verification/evt1_x2-dev6.1-spi.tr)

本版已通过离线构建和仿真。实机三槽切换、《俄罗斯方块》断电后分别读回三个位置，以及《马里奥大陆》实卡和蓝牙播放时的完整耗时仍待验证。此前 dev5.5 已在原配《俄罗斯方块》实机验过单槽断电恢复。首次测试请先备份重要进度。 [离线回归记录](../verification/tests-dev6.1.log)
