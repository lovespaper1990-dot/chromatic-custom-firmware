# Chromatic 4.6-dev6.2-test 卡带启动识别修正

dev6.1 在真机上完成了三个槽的写入和多次暖读档。保存约 1.21～1.22 秒，读档约 1.29～1.48 秒，包含挂载、传输、文件校验和恢复。首次保存及建立目录耗时 1.81 秒，以上记录来自同一张原配《俄罗斯方块》。

随后完整断电测试中，卡带识别码改变，界面提示无存档。只读文件检查确认，三个槽的文件都在卡上，大小和 CSS2 头符合预期。软件会按完整识别码选择文件，因此查找结果为空。

## 修正与核验

扫描器现在会在确认支持的卡头后，显式设置 ROM bank 1、高位 0 和 MBC1 mode 0，清掉探测阶段的 CRC，再从头计算。此前测试每次将模拟卡带预设为 bank 1，本版增加了初始 bank 0、257 和其他 MBC1 分页的用例。修正后的同一测试 ROM 得到一致的完整 CRC。无效卡头保持保守处理。

新增显式维护命令 `snapshot import OLD_ID_16HEX`，由维护者确认同一实体卡带后使用。它核对旧文件完整身份、格式及 CRC，复制到当前规范识别码下并重新校验，已有目标槽会跳过。本机已复制原有 1、2 号槽的各两代，3 号槽保留新的断电测试档。原文件均保留。迁移后的旧 2 号槽完整读档耗时 1.45 秒，用户确认回到原位置。复制通过 ESP32 FatFs 支持的独占文件写入接口完成。

增加串口只读命令 `snapshot files`，列出卡内快照的相对路径、大小及文件头，便于核对存档去向。

dev6.2 的 MCU 与 FPGA 已写入并校验。MCU 为 `0.13.8-dev6.2-test`，系统为 `4.6-dev6.2-test`，FPGA 基础版本仍为 18.14。原配《俄罗斯方块》的新 3 号槽已经经过 OFF、拔 USB、等待 10 秒、重新开机的测试，日志完成全部 10,341 字恢复，用户确认读档成功。本版保存实测 0.99～1.12 秒，完整读档 1.46 秒。

## 三槽操作

插卡开机后自动匹配游戏，在「主页 → 即时存档」按 START 切换 1、2、3 号槽，按 A 保存，按 B 再按 B 确认读档，确认时按 A 取消。每个槽独立轮换两代。1 号槽沿用旧路径，备份时保留整个 `SNAP` 文件夹。

当前采用通过原约束时序检查的构建，最差建立余量 +0.002 ns、保持 +0.194 ns。建立余量较窄，长期稳定性仍需实机验证。[本版时序报告](../verification/evt1_x2-dev6.2-spi.tr) · [目标回归记录](../verification/tests-dev6.2.log)
